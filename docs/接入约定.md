# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath、sources。raw 领取入口文件并记录元信息；structured 解析 SAM 文本并保存领域记录。structured 请求可通过 `sources` 指定来源清单内的一个或多个资源名（默认仅入口文件）；清单外资源或重复资源名返回 400。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，请求语法或来源清单错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

## 结构化记录约定

records 每条来源比对一条，主/次/补充比对不可合并删除，也不得按 QNAME 去重。每条记录包含：

- `recordId`：`来源文件名:L行号` 的稳定身份；另有 `source`、`line`（1-based 行号）、`lineOffset`（行首字节偏移）。
- `qname` 与 `flag`：FLAG 逐位解释（paired、properPair、queryUnmapped、mateUnmapped、reverse、mateReverse、firstInPair、secondInPair、secondary、qcFail、duplicate、supplementary），保留原始数值与未定义保留位。
- `isPrimary` / `isSecondary` / `isSupplementary`：三类标志独立保存，不互相派生。
- `location`：`rname` 与 `pos` 保留原值；`*` 缺值解释为 null，未比对位置 0 保留为 0，二者不混淆。`referenceSpan` 为 0-based 半开区间并保留原坐标；RNAME 未在 @SQ 声明时 `referenceDeclared=false` 并产生可定位 issue，区间仍按来源坐标解释。
- `cigar`：保留原始 CIGAR；逐操作标注 consumesReference / consumesQuery，并汇总 referenceConsumed、queryConsumed；`*` 以 missing=true 表示。M/D/N/=/X 消耗参考，M/I/S/=/X 消耗读段，H/P 两者都不消耗。
- `sequence` / `quality`：SEQ 的 `*` 缺值与空串区分；QUAL 缺值为 null。
- `readGroup`：RG 标签对应读组及其 @RG 声明；同名记录不同读组在关系索引中隔离。
- `pairing`：保留 RNEXT（含 `=` 与 RNAME 的解释）、PNEXT、TLEN 原值；`relationship.status` 取值：
  - `resolved`：本次已采记录中找到唯一可闭合的主比对对端，或 FLAG 标注 mateUnmapped；
  - `unresolved`：来源尚未提供可闭合对端（`mate-not-provided`，含对端在未交付文件中的情况）或来源内部存在歧义（`mate-ambiguous`），不替合作方补记录或猜测；
  - `not-applicable`：该记录本身不是配对模板（FLAG 0x1 未置位）。
- `tags`：A/i/f/Z/H/B 类型逐标签解释并保留类型；无法解释的标签保留原文并在 issues 定位。

coverage.files 逐文件保存 @HD、@SQ 序列字典、@RG 读组及范围外头部原文；coverage.relationships 汇总 resolved/unresolved/notApplicable 数量与未闭合清单；coverage.gaps 用中文说明来源缺口。
